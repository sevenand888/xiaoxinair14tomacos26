# 联想 82FF / Sonoma 14.8.9 与 Tahoe 26.7.1 操作手册

本手册保留 Sonoma 的第 1—18 步，接续 Tahoe 的第 19—27 步。安装 Sonoma 时，将仓库 sonoma14 目录内容复制到 C:\Hackintosh-Sonoma14，保持资料目录结构。首次使用前，先按第 19 步的资源下载与身份填写方法补齐所需文件。

## 交给 AI 的指令

```text
按本文操作联想小新 Air14 ITL 2021（82FF）。
先读取硬件、磁盘和当前 EFI，再执行对应步骤；修改配置前保存副本。
Sonoma 安装与维护按第 1—18 步；已有 Sonoma 安装 Tahoe 从第 19 步开始。
清空磁盘前，核对本次枚举的型号、容量和磁盘号，并取得用户对目标磁盘的确认。
IP、盘符、diskN 和挂载点以本次读取值为准。所有配置沿用本机同一组 SMBIOS 身份。
Tahoe 麦克风最终输入选择 Lenovo 82FF PDM0 internal microphone capture。
```

## 1. 准备文件

Windows 工作目录：

```text
C:\Hackintosh-Sonoma14
```

| 用途 | 文件 |
| --- | --- |
| 内置 SSD 用的基础 EFI | `资料/EFI-VESA-BT` |
| 恢复镜像 | `OC_OFFLINE/com.apple.recovery.boot/BaseSystem.dmg` |
| 完整安装包 | `MACOS_DATA/InstallAssistant.pkg` |
| 配置检查工具 | `资料/tools/ocvalidate.exe` |
| 图形驱动、图形配置 | `资料/graphics`、`config-graphics-dvmt60.plist` |
| 电池和亮度键 | `资料/power` |
| 原生 Wi-Fi 配置 | `资料/config-airport-only.plist` |

设置工作目录，检查 EFI 配置：

```powershell
$Root = 'C:\Hackintosh-Sonoma14'
$Kit = Join-Path $Root '资料'
& "$Kit\tools\ocvalidate.exe" "$Kit\EFI-VESA-BT\OC\config.plist"
```

## 2. 核对电脑和系统盘

本手册的硬件配置：

```text
Lenovo 82FF / 小新 Air14 ITL 2021
BIOS FKCN40WW V3.03
i5-1155G7 / 16 GB / Intel Iris Xe 8086:9A49
AX201 / ALC257 / I2C 触控板
系统盘：Samsung MZVL21T0HDLU，1,024,209,543,168 字节
```

使用这块 1 TB 三星盘作为内置系统盘。原 512 GB PM981a 不走这条安装路线。

制作内置盘安装介质时使用 `资料/EFI-VESA-BT`；先运行 GenSMBIOS，为 MacBookPro16,2 生成自己的 SystemSerialNumber、MLB、SystemUUID，并填写自己的 ROM。所有候选配置复用同一组身份，后续按字段合并改动。

## 3. 制作安装 U 盘

在 Windows 管理员 PowerShell 中枚举：

```powershell
Get-Disk | Format-Table Number,FriendlyName,SerialNumber,Size,PartitionStyle
Get-Volume | Format-Table DriveLetter,FileSystemLabel,FileSystem,Size
```

选中至少 32 GB 的 U 盘。通过本次设备枚举选择自己的 U 盘。

用户确认目标后，通过 DiskPart 建立两个分区：

```text
select disk <本次枚举出的U盘号>
detail disk
clean
convert mbr
create partition primary size=2048
format fs=fat32 quick label=OC_OFFLINE
assign
create partition primary
format fs=exfat unit=131072 quick label=MACOS_DATA
assign
exit
```

重新查询盘符，分别设为 `$BootRoot`、`$DataRoot`，例如 `J:\`、`K:\`。复制：

```powershell
Copy-Item -LiteralPath "$Kit\EFI-VESA-BT" -Destination "$BootRoot\EFI" -Recurse
Copy-Item -LiteralPath "$Root\OC_OFFLINE\com.apple.recovery.boot" -Destination "$BootRoot\com.apple.recovery.boot" -Recurse
Copy-Item -LiteralPath "$Root\MACOS_DATA\InstallAssistant.pkg" -Destination "$DataRoot\InstallAssistant.pkg"
```

目标结构：

```text
OC_OFFLINE
  EFI/BOOT/BOOTx64.efi
  EFI/OC/config.plist
  com.apple.recovery.boot/BaseSystem.dmg
MACOS_DATA
  InstallAssistant.pkg
```

复制完成后安全弹出 U 盘。

## 4. 设置 BIOS 并进入恢复环境

1. 关闭 BIOS Secure Boot，开启 USB Boot。
2. 插入 U 盘，接电源。
3. F12 或 Fn+F12 选择 `UEFI SG Flash`。
4. OpenCore 菜单选择 `OC_OFFLINE (external) (dmg)`。
5. 打开“实用工具 → 终端”。

保留以下引导设置：

```text
Misc/Boot/Timeout = 0
Booter/Quirks/EnableWriteUnprotector = true
Booter/Quirks/RebuildAppleMemoryMap = false
Booter/Quirks/SyncRuntimePermissions = false
```

恢复环境命令：

```sh
sysctl kern.boottime kern.bootargs
mount
diskutil list physical
```

根卷保持只读。恢复阶段直接在终端执行后续命令。

## 5. 挂载介质并准备目标卷

先用 `diskutil list physical` 找出 U 盘 FAT32、exFAT 分区和 1 TB 三星系统盘。

如卷未自动挂载，按本次实际分区号挂载：

```sh
mkdir -p /Volumes/OC_OFFLINE /Volumes/MACOS_DATA
/sbin/mount_msdos /dev/<U盘FAT32分区> /Volumes/OC_OFFLINE
/sbin/mount_exfat /dev/<U盘exFAT分区> /Volumes/MACOS_DATA
```

将本次确认的目标物理盘号赋给 `TARGET_DISK`，例如 `disk0`，再执行：

```sh
diskutil info "$TARGET_DISK"
```

确认型号含 `MZVL21T0HDLU`、容量为 `1024209543168`，并取得用户抹盘授权后：

```sh
diskutil eraseDisk APFS 'Macintosh External' GPT "/dev/$TARGET_DISK"
diskutil info '/Volumes/Macintosh External'
```

记录本次磁盘号、卷 UUID 和 EFI 分区号，后续都用这次记录。

## 6. 展开离线安装器

在同一终端或同一脚本中执行：

```sh
TARGET='/Volumes/Macintosh External'
PKG='/Volumes/MACOS_DATA/InstallAssistant.pkg'
WORK="$TARGET/macOS-Installer-Offline"
mkdir -p "$WORK/logs"
caffeinate -dims > "$WORK/logs/caffeinate.log" 2>&1 &
CAFFEINATE_PID=$!
pmset -a sleep 0 displaysleep 0 disksleep 0
pkgutil --expand-full "$PKG" "$WORK/InstallPackage" > "$WORK/logs/expand.log" 2>&1
```

在展开结果中定位唯一的安装应用：

```sh
find "$WORK/InstallPackage" -type d -name 'Install macOS Sonoma.app' -prune
```

把输出路径赋给 `APP`。展开后的路径一般为：

```sh
APP="$WORK/InstallPackage/Payload/Applications/Install macOS Sonoma.app"
mkdir -p "$APP/Contents/SharedSupport"
ln -sfn "$PKG" "$APP/Contents/SharedSupport/SharedSupport.dmg"
"$APP/Contents/Resources/startosinstall" --usage
```

这里的 `SharedSupport.dmg` 链接到原始 `InstallAssistant.pkg`；安装准备结束前保持 MACOS_DATA 挂载。

检查空间：

```sh
df -h "$TARGET" /private/var/log /Library/Logs/DiagnosticReports
pmset -g assertions
```

安装输出保存到目标盘的 `logs` 目录。若 DiagnosticReports 的 RAM 卷容量不足，先备份其中内容，使用 `hdiutil attach -nomount ram://131072` 创建 64 MiB RAM 盘，核对它是 Virtual/Disk Image 后格式化为 HFS，复制旧内容，再以 `union,nobrowse` 挂回 `/Library/Logs/DiagnosticReports`；保留原 RAM 盘用于回退。

## 7. 启动安装并跨重启继续

先确保没有另一轮安装器正在运行，再创建本轮唯一标记：

```sh
ps -axo pid,comm | grep -E 'startosinstall|osinstallersetupd'
mkdir "$WORK/launch.started"
```

有正在运行的安装器，或 `launch.started` 已存在时，读取本轮日志继续观察，不重复启动。

后台启动：

```sh
(
  trap '' HUP
  env __OSINSTALL_ENVIRONMENT=1 \
    "$APP/Contents/Resources/startosinstall" \
    --volume "$TARGET" --agreetolicense --rebootdelay 300
  code=$?
  printf '%s\n' "$code" > "$WORK/logs/install.exit"
) > "$WORK/logs/install.log" 2>&1 < /dev/null &
```

观察：

```sh
tail -n 60 "$WORK/logs/install.log"
```

OpenCore 每次出现后按下面选择：

| 菜单情况 | 选择 |
| --- | --- |
| 仍有 `macOS Installer` | `macOS Installer` |
| Installer 消失，出现系统卷 | `Macintosh External` |
| 需要维修 / 重新进恢复环境 | `OC_OFFLINE (external) (dmg)` |

“剩余不到一分钟”时保持供电并观察，随后继续等待自动重启。出现国家选择后进入第 8 步。

## 8. 首次设置、中文和 SSH

1. 国家/地区选中国大陆。
2. 数据迁移选“以后”或“现在不传输”。
3. 创建自己的本地管理员账户，密码由用户输入。
4. 设置 → 通用 → 语言与地区，把简体中文拖到第一位。
5. 用 HeliPort 连接 Wi-Fi；系统中的 Ethernet/en0 就是这套无线连接。
6. 设置 → 通用 → 共享 → 远程登录，允许自己的管理员账户。
7. 打开终端读地址：

```sh
networksetup -listallhardwareports
ipconfig getifaddr en0
sw_vers
```

Windows 使用 `ssh <管理员用户名>@<当前IP>`，端口为 `22`。将已有客户端公钥加入用户 `~/.ssh/authorized_keys`，目录权限 700、文件权限 600；之后使用密钥连接。

连接后采集：

```sh
sw_vers
sysctl kern.boottime kern.bootargs
diskutil list physical
system_profiler SPDisplaysDataType
pmset -g batt
```

把安装阶段修改的 `sleep/displaysleep/disksleep` 恢复为日常设置，例如接电时 10/10/10 分钟，再进入驱动配置阶段。

## 9. 迁移到内置 EFI，脱离 U 盘

1. 根据第 5 步记录找出内置 1 TB SSD 的 EFI 分区，挂载到 `/Volumes/EFI`。
2. 把现有 EFI 内容备份到用户目录；保留已有 `EFI/Lenovo` 或其他厂商目录。
3. 从 U 盘复制 `EFI/BOOT` 和 `EFI/OC` 到内置 EFI。已有同名目录先移到本次备份目录。
4. 用 ocvalidate 检查配置。
5. 关机，拔下 U 盘，从内置 SSD 的 UEFI 入口启动，选择 `Macintosh External`。
6. 进入桌面后检查 `diskutil list physical`，并连接 SSH。

至此得到内置盘启动、VESA 显示、itlwm 联网、蓝牙/声音/输入驱动的基础系统。保存一份完整 EFI 和系统盘数据备份，再做后续修改。

## 10. 在现有系统继续：先备份并检查配置

以下命令在正式系统中执行，使用当前管理员账户。

```sh
sw_vers
sysctl kern.boottime kern.bootargs
diskutil list physical
sudo diskutil mount <本次确认的内置EFI分区>
```

将 `/Volumes/EFI/EFI`、`/Library/KernelCollections/AuxiliaryKernelExtensions.kc`、`/Library/Extensions` 中的图形驱动及 `/Library/GPUBundles` 保存到带日期的新目录。

所有配置编辑都先复制 `config.plist`，用 Python `plistlib` 按 `BundlePath` 查找驱动条目，生成新文件；ocvalidate 通过后再原子替换内置配置。

## 11. 配置 Iris Xe 图形加速

在本包 `资料/graphics` 中取出自编译 `WhateverXe.kext`。解压 `AMFIPass-v1.4.1-Mod-RELEASE.zip`，取出 `AMFIPass.kext`。

图形包从 https://github.com/b00t0x/WhateverXe-Graphics/releases/tag/v0.3.1 自行下载。将上述 Kext 复制到内置 EFI 的 `OC/Kexts`，使用 `config-graphics-dvmt60.plist` 对照当前配置，设置：

```text
WhateverGreen.kext  Enabled=false
WhateverXe.kext     Enabled=true
AMFIPass.kext       Enabled=true

boot-args:
-v keepsyms=1 debug=0x100 -vi2c-force-polling alcid=101 -allow3d -disablegfxfirmware -igfxdvmt

DeviceProperties/Add/PciRoot(0x0)/Pci(0x2,0x0):
framebuffer-patch-enable = Data 01000000
framebuffer-stolenmem    = Data 0000C003

SecureBootModel=Disabled
csr-active-config=Data 03080000
Timeout=0
```

本机 DVMT 为 60 MiB，使用上面这组显存配置。保持原有机型身份、USB、声音和触控板设置。

先停用 UU 自启动，再重启：

```sh
sudo launchctl disable "gui/$(stat -f %u /dev/console)/com.netease.uuremote.agent"
sudo launchctl disable system/com.netease.uuremote.daemon
sudo launchctl bootout "gui/$(stat -f %u /dev/console)" /Library/LaunchAgents/com.netease.uuremote.agent.plist
sudo launchctl bootout system /Library/LaunchDaemons/com.netease.uuremote.daemon.plist
```

没有安装 UU 时跳过这些命令；已退出的任务返回错误时，以进程列表确认是否仍有 UU 进程。

重启后检查 WhateverXe 与 AMFIPass 已加载，再安装图形包：

```sh
kextstat | grep -E 'WhateverXe|AMFIPass'
sudo installer -pkg '<拷贝到Mac的路径>/WhateverXe-Graphics-0.3.1.pkg' -target /
```

安装完成后正常重启。新安装系统使用包安装器生成的 AuxKC，不复制旧系统的 AuxKC。

## 12. 检查加速与视频编码

先保持 UU 关闭，执行：

```sh
system_profiler SPDisplaysDataType
kextstat | grep -E 'WhateverXe|AppleIntelTGL'
ioreg -l -w0 -d 1 | grep -E 'TGLRecoverySinglePass|TGLAcceleratorAdmissionReady'
```

看到 Iris Xe、Metal 和恢复补丁 Ready 后，依次操作：

1. 拖动 Finder 和系统设置窗口，观察桌面响应。
2. 播放本地视频。
3. 单独测试 H.264 软件编码，再测试硬件编码。
4. 连接外接显示器，测试拔插和扩展桌面。
5. 最后启动 UU，先以 1080p / H.264 测试。

新装系统先执行 `xcode-select --install`，完成命令行工具安装；把本包中的 `graphics/vt-encode-probe.m` 复制到 Mac，再编译：

```sh
clang -fobjc-arc -O1 vt-encode-probe.m -framework Foundation -framework VideoToolbox -framework CoreMedia -framework CoreVideo -o vt-encode-probe
./vt-encode-probe h264-software
./vt-encode-probe h264-hardware
```

每次编码测试后检查 `/Library/Logs/DiagnosticReports` 的新 `gpuRestart`、panic 和 WindowServer 报告。出现 GPU 错误就保存本轮日志，停止叠加负载，按第 17 步回退。

需要重新编译时，在已有源码目录执行：

```sh
export SDKROOT="$(xcrun --show-sdk-path)"
python3 tools/test.py
python3 tools/build.py --release --output build/RELEASE
```

源码从 https://github.com/b00t0x/WhateverXe 的 0.6.0 标签获取，按项目构建说明准备 MacKernelSDK 和 Lilu 开发依赖后编译。

## 13. 恢复电池

先启用 `SMCBatteryManager.kext`，顺序保持在 `VirtualSMC.kext` 后面。检查配置后写入内置 EFI，再正常重启。

```sh
kextstat | grep SMCBatteryManager
pmset -g batt
system_profiler SPPowerDataType
```

看到电量后，拔掉再接上充电器，检查电源来源和充电/放电状态随之变化。

## 14. 恢复亮度快捷键

把资料目录 `power/BrightnessKeys.kext` 放入内置 `EFI/OC/Kexts`，添加对应 `Kernel/Add` 条目，放在 Lilu 后面：

```text
BundlePath=BrightnessKeys.kext
ExecutablePath=Contents/MacOS/BrightnessKeys
PlistPath=Contents/Info.plist
Arch=Any
Enabled=true
MinKernel=23.0.0
MaxKernel=空
```

保留 SSDT-XOSI、SSDT-PNLF。写入配置并重启，按增/减亮度键，必要时配合 Fn；同时观察控制中心亮度滑块和面板亮度。

按键仍无反应时，读取 BrightnessKeys 的 `BrightnessPanel`、`BrightnessKeyRouted`，并检查 ACPI `_Q11/_Q12` 对 DD1F 的 0x87/0x86 通知，按缺失的一段修复。

## 15. 配置睡眠唤醒

用户在机器旁时操作：

1. 关闭 UU，退出持续播放视频或录音的程序。
2. 运行 `pmset -g assertions`，处理列出的睡眠阻止者；若仍为 `.Display_boot`，先回第 12 步处理 framebuffer 接管。
3. 将 `pmset -g assertions`、`pmset -g custom`、`pmset -g batt`、`system_profiler SPPowerDataType` 的输出保存为睡前记录。

4. 从苹果菜单手动睡眠，等待约 30 秒，再按电源键唤醒。
5. 检查显示、键盘、触控板、Wi-Fi、蓝牙和 USB，保存睡后采集：

```sh
pmset -g assertions
pmset -g batt
pmset -g log | tail -n 80
```

6. 通过后再测试合盖/开盖。
7. 若立即唤醒，读取 Wake Reason，定位对应 USB/网卡唤醒源；若黑屏或重启，先检查图形和 sleep/wake panic，再改对应驱动。

## 16. 切换系统 Wi-Fi 开关

先接好备用网络，并从 Windows 经备用地址连入 Mac 的 SSH。三星 S25+ USB 共享需先打开手机“USB 网络共享”，再在 Mac 检查：

```sh
networksetup -listallhardwareports
ifconfig -l
```

若没有新增网络接口，检查手机 USB 协议并安装与之对应的 RNDIS 用户态工具；若有接口则读取 IP 和路由。手机 NAT 下不能直接连入时，让 Mac 通过备用网络主动建立到 Windows 的反向 SSH 通道，或改用 USB 有线网卡接同一台路由器。

备用 SSH 通道工作后，修改当前配置：

```text
itlwm.kext         Enabled=false
AirportItlwm.kext  Enabled=true
```

使用现有的 AirportItlwm 2.3.0 Sonoma14.4 版。检查配置，保存回退副本，再重启。

在系统 Wi-Fi 页面打开开关，扫描、连接家中无线网；读取新 IP，再测试 SSH、断开重连和重启后重连。

若能联网但苹果服务受 LinkQuality 影响，检查 `scutil` 中对应接口的 LinkQuality，使用 OpenIntelWireless PR #1056 / DexterSLamb fork 的 Sonoma14.4 修复版继续处理。

## 17. 回退

### 只撤回电池/亮度配置

恢复修改前保存的 config.plist，再重启。

### 撤回 AirportItlwm

恢复切换前的 config.plist，或把 `AirportItlwm=false`、`itlwm=true`；正常启动后使用 HeliPort 联网。

### 撤回图形测试

系统进不去时，从安装 U 盘的 OpenCore 选择恢复镜像，挂载目标 Data 卷和 EFI。

新装系统的图形回退：使用本轮保存的 EFI、原始 AuxKC，撤出本轮安装的 TGL Kext、GPUBundles 和收据，再恢复 VESA EFI。保持这三个部分配套。

### 恢复 UU 自启动

显卡和编码测试完成后执行：

```sh
sudo launchctl enable "gui/$(stat -f %u /dev/console)/com.netease.uuremote.agent"
sudo launchctl enable system/com.netease.uuremote.daemon
```

再从应用程序打开 UU。

## 18. 收尾

1. 保存最终完整 EFI、系统版本和驱动版本。
2. 保存当前成功启动的日志及回退文件。
3. 将安装器展开目录归档到其他盘，再清理系统盘上的临时安装文件。
4. 把用户实际通过的功能写回成功记录。
5. 后续每次改动从这份最终 EFI 新建副本，不覆盖救援 U 盘。


## 19. 准备 Tahoe 文件和本机身份

本节接续 Sonoma 的安装结果。本手册按以下顺序操作：**Sonoma 展开 Tahoe 安装器 → Tahoe 恢复环境安装 → 首次进入桌面 → 修复原生 Wi-Fi 和图形 → 修复内置麦克风 → 迁入内置硬盘**。原机器于 10 月 31 日完成安装和迁盘，11 月 1 日完成麦克风修复。

Windows 上把仓库放在 `C:\Hackintosh-82FF`，在仓库根目录执行：

```powershell
python tools/fetch-resources.py sonoma14/资源来源.json
python tools/fetch-resources.py tahoe26/resources.json
```

工具从上游下载缺少的组件，校验 SHA256 后补齐对应路径。Apple 安装资源单独准备：

| 文件 | 版本 / 放置位置 |
| --- | --- |
| Tahoe 恢复镜像及 chunklist | Apple 来源，放入 U 盘启动分区 `com.apple.recovery.boot/` |

## 28. 修复合盖/开盖黑屏（Tahoe 显示唤醒）

Tahoe 下合盖会强制显示器进入睡眠；再开盖唤醒时，WhateverXe 的内屏 eDP 链路训练可能失败，
表现为**屏幕黑掉但系统仍在运行**（SSH、Tailscale 可连，声音、麦克风正常）。
日志中会出现 `LINK_TRAINING ... failed`、`FB0 is not enabled`、`Hotplug received on closable display - bailing out`。

原理、判定命令、完整配置与回退方法见 [合盖黑屏与显示唤醒](合盖黑屏与显示唤醒.md)。

本机采用的处理是**禁止显示器进入睡眠**，让 eDP 不需要重新训练：

```sh
sudo pmset -a disablesleep 1 displaysleep 0 sleep 0 lidwake 1
```

再加两个系统级任务长驻保持（完整 plist 与脚本见上文的文档）：

- `com.user.caffeinate`：`caffeinate -d -i -s` 常驻，阻止显示器/系统空闲睡眠；
- `com.user.powermgmt-enforce`：每 30 秒检查一次 `SleepDisabled`，不是 1 就重新应用，
  防止设置被系统或其它程序重置。

UU远程 的「防睡眠」开关也可以作为补充。合盖时内屏背光保持点亮（合上看不到），
**LCD 没有烧屏风险**，但会耗电并轻微发热，建议插电、通风使用。
出现黑屏时系统仍在运行，远程 `sudo shutdown -r now` 重启即可恢复，不要直接长按电源强关。

HDMI 外接显示目前仍未修复，与本问题无关。
